# 仕様（docs/specs/）

このディレクトリに、**何を・なぜ作るか**を定める仕様を置きます。仕様はここに記述する、というのがこのリポジトリの原則です（行動規範の原則 P-8）。

- 仕様は人間が書き、レビューして承認します。エージェントは、承認された仕様に書かれたことだけを実装します（原則 P-4）。
- Issue の「関連する仕様」と、Pull Request の「関連する仕様」には、このディレクトリのファイルへの相対パスを書きます。
- 実装の途中で仕様と現実の食い違いを見つけたら、同じ Pull Request の中で仕様も更新し、何がなぜ変わったかを「仕様差分」に書きます（原則 P-5）。
- Issue が設計判断を求めている場合の設計計画は、`<Issue番号>-<件名>.md` という名前で置きます（慣習 C-5）。

仕様の書き方は、[「7 つの工程」のサンプル](../../archive/examples/README.md)を参考にしてください。運用の全体像は [Issue 駆動開発ガイド](../guides/issue-driven-sdd.md) にあります。
